Help & About

Quick start

  1. Filter the dashboard to the job names, status, type, and period you want to investigate.
  2. Review failures and open View details for the complete read-only CONNX response.
  3. Choose an analysis scope, run AI analysis, then assign and track the recommended follow-up.

Filters
Apply to job history, failure summaries, asset panels, exports, and the next AI analysis. Reset restores the default 24-hour view.
Status
Success means CONNX reported completion. Failure means the operation stopped; open its details before deciding on remediation.
Auto-refresh
Reloads every 30 seconds and persists in this browser. It pauses while you edit a field or have a panel or dialog open.
Exports
CSV exports filtered job history. Markdown and PDF exports contain saved AI findings and operator follow-up.
Finding follow-up
Use status, owner, notes, and a validated HTTP(S) runbook link to record the operational response.

Operator review is required. AI findings are recommendations, not automated changes or confirmed root causes.

Analysis scopes

  • All filtered jobs uses every displayed matching record.
  • Failures only excludes successful operations.
  • Selected history rows sends only checked rows.

What may be sent to Azure OpenAI

A field-selected copy of up to {{ help_about.history_limit }} displayed jobs: outcome, object name and type, sync type, timestamps, duration, row counts, and the compact error summary. Dashboard credentials, bearer tokens, Azure keys, and operator follow-up are never included.

Current controls

  • Redaction: {{ help_about.redaction }}
  • Quota: {{ help_about.hourly_limit }}/hour and {{ help_about.daily_limit }}/24 hours per operator identity
  • Saved-analysis retention: {{ help_about.retention_days }} days
  • Destination pre-flight: {{ help_about.preflight }}

Login or connection failure

Verify the server identity, TLS setting, Windows AD credentials, network access, and CONNX REST service availability.

Multiple tables fail together

Correlate timestamps with destination availability, listener health, maintenance, restarts, and network events before changing individual mappings.

Destination pre-flight fails

Resolve the configured health check first. When pre-flight is required, AI analysis is deliberately blocked until the endpoint recovers.

AI analysis does not start

Confirm matching history exists, the deployment is configured, the requested scope contains rows, and the operator quota has not been reached.
